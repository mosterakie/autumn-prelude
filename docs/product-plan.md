日期：2026 年 10 月 5 日<br>
用途：记录秋序已确定的产品需求、Agent 职责、服务分工和前后端开发边界。

中文名：秋序<br>

## 1 产品定位与总体判断

这个方向可行。建议定位为一个长期使用的个人网站：对外展示个人记录、项目和收藏，让访客注册后留言；对内提供能够查询私人资料、延续任务并使用工具的 AI 助手。

项目的价值在于把“我写过什么、收藏过什么、正在研究什么、需要处理什么”连接起来。第一版应让个人内容和私人助手形成完整的日常使用流程，再按实际互动情况扩大社区。

首版组合是：**个人主页＋手记与收藏＋邮箱注册与留言＋普通用户 AI 问答＋站长私人助手**。普通用户可以体验 AI，联网搜索只给站长使用。完整论坛与自动性格画像仍放到后续。

部署暂缓，不列入当前开发阶段的验收条件。先完成方案、代码结构和本地可验证的功能；域名、服务器与上线安排以后再定。英文名已确认，当前进入初始仓库整理阶段，应用功能尚未实现，网站尚未部署。

### 已确认的需求

### 仍属于建议的内容

先做留言区；使用单一角色和一套 Agent 工作流；按话题持续保存会话；不自动生成普通用户的性格画像。前端暂沿用 Next.js 建议；初始仓库采用 frontend 和 backend 两个目录，后端包含 Agent。

邮箱加密码、24 小时冷却和每日 10 次额度已经确定。日额度建议按 Asia/Shanghai 自然日零点重置；每分钟限速、并发数、管理员二次验证形式和操作确认规则仍可调整。百炼的向量化与重排序分工是当前建议，不代表已经锁定具体模型。

## 2 页面与内容组织

网站不设置整站登录门槛。首页、已公开文章、公开收藏、关于页面和已审核的公开留言可直接浏览；提交留言、发送 AI 消息、查看个人对话和进入管理功能时才要求登录。登录后返回原操作位置，保留尚未提交的输入。后端按具体接口执行鉴权，前端隐藏按钮不能代替权限检查。

参考站以个人介绍、作品、关于和文章入口组织内容。可以借鉴这种清晰的个人站结构，再加入你需要的收藏、留言和 AI 入口。[参考网站](https://gegarron.com/)

| 页面 | 主要内容 | 首版范围 |
| --- | --- | --- |
| 首页 | 个人介绍、最新手记、精选收藏、助手入口、外部账号 | 必做 |
| 手记 | 长文章、短记录、标签、公开或私密状态 | 必做 |
| 收藏 | 网址、标题、备注、标签、公开或私密状态 | 必做 |
| 留言板 | 留言、站长回复、举报、审核 | 必做 |
| 关于 | 个人简介、兴趣、账号、项目与仓库链接 | 必做 |
| 对话 | 历史会话、引用来源、任务进度、助手形象 | 必做 |
| 管理区 | 助手管理入口、资料处理状态、公开范围、保存策略、操作记录；保留表单兜底 | 必做 |
| 论坛 | 用户主题帖、分区、讨论与通知 | 后续 |

文章、收藏和知识资料具有明确且可修改的可见性。私人日记与草稿默认仅站长可见；站长可通过助手将指定内容公开或收回。公开页面、公开 AI 检索与原文件下载分别设置，不能因公开一条收藏就自动公开站长的备注、抓取正文或私人分析。

外部账号链接、项目仓库链接、第三方登录是三件不同的事。前两项只是展示入口；“使用 GitHub 登录”涉及账号绑定与身份验证，可以以后再加。具体账号、仓库和邮箱由站长提供，原型不填入虚构联系方式。

### 留言区能否发展成论坛

可以，但论坛会增加持续运营工作。留言区主要围绕站长和内容互动；论坛允许用户主动发起主题，还需要分区、主题管理、举报处理、通知和版务规则。

第一版建议支持独立留言与文章评论，回复层级控制在一至两层。底层保留内容 ID、作者 ID、父回复 ID、审核状态与举报记录。未来有持续讨论需求时，再增加独立主题帖和分区。

初期优先保证邮箱验证、新用户审核、内容长度限制、举报与封禁可用。是否开放用户上传附件另行决定。

## 3 视觉方向

### 推荐方案

**构成主义排版＋阮梅启发的青玉色系＋局部二次元形象。**

采用大字号标题、不对称分栏、清晰网格、几何圆形与斜切色块。已制作硬角和圆角两版首页供比较，最终圆角程度尚待选择。正文保持规整易读；首页使用阮梅常规立绘，对话与任务反馈使用阮梅像素小形象。

正式中文名为“秋序”，英文名为 Autumn Prelude。已有概念图仍使用旧占位名“青序”，后续页面实现与新设计稿统一改为正式名称。阮梅为原方案，已另制停云圆角版供对比；两版素材先保留。配色为设计提案，不是官方色值，角色切换不影响业务与权限设计。

| 用途 | 色彩 | 建议色值 |
| --- | --- | --- |
| 页面底色 | 暖瓷白 | #F2EFE5 |
| 主标题与深色区域 | 青黛 | #163F43 |
| 主色块 | 玉青 | #8CB9AA |
| 次级底色 | 浅玉 | #DCE8DA |
| 少量点缀 | 旧金 | #BDA575 |

金色适合细线与装饰，正文和按钮优先使用深色与浅色的高对比组合。开发时需要实测文字对比度、键盘操作和移动端可读性。

### 常规立绘与像素形象的分工

主页继续使用阮梅常规立绘。像素小形象用于聊天入口、对话页以及任务处理时的状态反馈，属于网站内的角色组件。

首版建议制作六种状态：待机、倾听、思考、执行、完成和需要处理。它们分别映射到真实任务事件；只展示“思考动画”不能代替任务进度。角色可以收起，尊重减少动画设置，不遮挡正文和留言表单。

像素角色和主页立绘属于同一个助手，共用角色设定与当前会话。角色外观不决定权限。移动端优先展示内容，将立绘缩为适当尺寸，把像素形象作为轻量入口；语音不列入当前范围。

## 4 Agent 重新设计

### 定位与角色

Agent 同时承担“普通用户的站内向导”和“站长的私人助手及管理入口”。使用同一个阮梅角色设定，但资料范围和可用工具由服务端身份决定。普通用户可以聊天和查询公开知识；站长额外拥有联网搜索、网页入库、内容编辑与设置管理能力。

角色表达保持平静、准确、好奇和克制，标明 AI 身份。角色扮演不改变事实判断与权限；没有资料依据时说明不确定。首版不模仿站长的人格，不维护多角色或多 Agent 协商体系。

### 工具按站内业务定义

| 能力 | 普通用户 | 已额外验证的站长 |
| --- | --- | --- |
| 聊天与会话续接 | 自己的会话 | 自己的公开或私人会话，模式隔离 |
| 查询站内文章与资料 | 允许公开 AI 使用的内容 | 本人私人资料及公开内容 |
| 联网搜索 | 不开放 | 搜索、阅读结果并引用 |
| 抓取指定网页 | 不开放 | 收藏链接、正文入库与手动刷新 |
| PDF 与 Word 入库 | 不开放 | 上传、解析、检索、更新与删除 |
| 文章与收藏管理 | 不开放站长管理工具 | 创建、修改、分类、公开与收回 |
| 公开范围管理 | 不开放 | 查询或修改指定对象与公开字段 |
| 保存策略管理 | 仅按账号功能管理自己的会话 | 查询策略、调整范围与保存期限 |

网页搜索与抓取都是站长能力。普通用户发送一个网址时，助手可以处理用户直接提供的文本、或检索已获准公开的站内资料，但不能借“读一下这个网页”绕过限制发起联网请求。

每个工具接收结构化参数，例如文章 ID、字段变更和目标范围，调用后端业务服务。Agent 不直接执行任意 SQL，不获得数据库管理员连接，也不通过生成脚本任意修改应用设置。

### 统一工作流程

1. 验证账号、额外验证状态、冷却与额度，并校验会话归属。
2. 读取最新权限，给本次请求组装资料范围与工具白名单。
3. 识别用户是在提问、添加资料、修改内容，还是调整设置。
4. 查找目标对象并生成具体操作；名称不唯一时给出候选项，不猜测目标。
5. 业务服务校验参数、权限与影响范围，按规则直接执行或展示待确认结果。
6. 持久化结果、来源与操作记录，向前端返回实际完成情况。

流式文本与后台任务状态分开管理。长任务通过任务 ID 持久保存，页面关闭后仍能查到结果；模型生成一句“已经修改”不算成功，只有业务服务返回已提交状态才能报告完成。

LangGraph 可用于保存任务状态和等待用户输入，暂停后再恢复；授权检查、操作是否成功与重试去重仍由应用完成。[LangGraph 中断与恢复](https://docs.langchain.com/oss/python/langgraph/interrupts)

### 什么可以直接执行

目标与结果明确的查询、收藏、加标签、保存草稿以及收回公开内容，可以在站长明确指令下直接执行。对于明确指向现有内容、且指定了公开字段的发布指令，可将这条指令本身作为授权，不必机械地重复确认。

助手新生成的内容尚未被站长看过，或指令涉及整类资料批量公开、包含范围不明的私人备注、缩短期限并清理历史数据时，先展示具体影响，再请站长决定。日常低影响操作可撤销；彻底删除与公开暴露不能承诺完全恢复。

如需确认，确认记录绑定具体对象、内容版本、参数和站长身份。等待期间内容变化或管理员验证过期，恢复执行前重新检查，不能凭一句“确认”批准另一项操作。

### 首版应打通的例子

| 站长指令 | 应执行的动作 | 返回结果 |
| --- | --- | --- |
| “收藏这个网址，并把正文放入私人知识库” | 新建收藏、抓取正文、解析入库 | 收藏位置、入库状态、来源链接 |
| “只把这条收藏的标题和网址公开，备注保持私密” | 修改公开字段并同步公开页面 | 已公开字段与未公开字段 |
| “把上周那篇记忆设计文章改成私密” | 定位文章；关闭公开页面和公开 AI 访问 | 修改结果、受影响入口 |
| “用这些资料整理一篇手记” | 检索并生成私密草稿 | 可编辑草稿与引用 |
| “看看当前有哪些内容公开了” | 查询当前公开列表和字段 | 可核对的清单 |
| “日志以后保留 180 天，历史先不动” | 预览并设置仅适用于后续日志的策略 | 生效范围、时间与策略版本 |

上述期限调整只是未来接口能力示例；当前文章、收藏、聊天和日志的实际默认策略全部为永久。

保留基础管理表单作为纠错与兜底。表单和助手调用同一套业务服务，避免“聊天改了设置，后台显示另一份状态”。

## 5 身份权限与统一问答入口

可以使用一个 `POST /api/ask` 入口，同时服务公开问答和私人助手。

正确的顺序是：**验证登录状态 → 读取服务端身份与额度 → 校验会话归属 → 确定资料范围和工具 → 执行检索或任务 → 返回结果并记录用量**。

用户在消息里写“我是管理员”，或前端传来 `role=admin`，都不能改变权限。每个查询和工具调用还要单独检查权限。FastAPI 支持在应用代码中执行认证与权限检查，声明权限本身并不等于自动完成授权。[FastAPI 权限文档](https://fastapi.tiangolo.com/advanced/security/oauth2-scopes/)

| 身份 | 内容与知识范围 | 对话与工具 |
| --- | --- | --- |
| 未登录访客 | 所有已公开且可浏览的站内页面 | 无须登录即可浏览；留言、AI 提问和个人数据操作时要求登录 |
| 已注册普通用户 | 允许公开 AI 使用的知识、自身会话 | 限额聊天与站内问答、留言；不能联网搜索或抓取网页 |
| 站长普通登录状态 | 公开功能 | 进入私人助手前再次验证 |
| 站长已完成额外验证 | 本人的私人资料及公开知识 | 私人检索、联网搜索、资料入库、内容和设置管理 |

额外验证建议采用独立管理员角色，加上 Passkey 或 TOTP 等二次验证。前端用清晰的“公开问答”和“私人工作台”提示当前模式，避免站长误把私人问题发到公开模式。

统一 API 入口不意味着共享对话、缓存或向量检索范围。文章、原文件、分块、会话、记忆、下载链接与缓存都需要按身份和可见性隔离。向量查询应先限定允许读取的资料，再排序和送给模型。

私人助手会话与普通用户问答会话分别保存；切换模式不直接沿用已有的私人上下文。这里的“公开问答”指使用公开资料，并不意味着聊天记录会被公开。管理员身份失效后，历史私人对话和待执行任务同样要重新鉴权。

### 动态公开的规则

首版对文章、收藏和知识资料支持私密与公开两种可见性；按对象设置，也可以批量修改。文章的草稿或发布状态与可见性分开：私密草稿不会因修改某个标签而自动发布。

建议分别记录页面可见性、公开字段、是否允许公开 AI 引用，以及是否允许下载原文件。发布一条收藏的标题与网址，不自动发布私人备注和全文快照；公开文档摘要，不自动开放 PDF 或 Word 原件。公开 AI 只能使用显式发布的内容版本和字段。

聊天和日志默认私密。站长若要分享自己的对话，助手应生成指定片段的独立分享版本，展示范围后再发布；不能把包含其他用户聊天或系统内部信息的整类记录一起公开。公开文章引用私人资料时，同样检查引用片段的公开授权。

从公开改回私密时，同步关闭公开页面、检索入口、引用预览与原文件下载，失效相关缓存。进行中的任务在返回前再次校验权限；后续会话摘要、历史检索上下文和检查点不能继续携带已撤回的资料供新回答使用。实现上为资料保留来源依赖和权限版本，不只改页面上的开关。

已向访客发出的文字、第三方缓存或截图无法保证收回；“改成私密”保证的是本站后续访问与使用停止，而不是抹去已经发生的传播。

### system prompt 的职责

system prompt 用于表达风格、工作步骤、引用要求和工具使用说明。账号限流、注册冷却、管理员验证、资料访问与发布权限由服务端控制，不能委托给模型自行遵守。

模型可能读取网页或 PDF 中的指令性文字。这些内容应当作为资料，而不能提升权限、改写系统规则或自行触发外部操作。

## 6 会话与记忆设计

### 会话如何划分

以一个主题或任务对应一个 conversation。用户主动点击“新对话”时创建新的会话；刷新页面、关闭网页或隔天回来，不自动清空，也不强制另起会话。

允许同一个用户同时拥有多个会话，并提供历史列表、重命名、删除与继续讨论。明显换题时，助手可以建议新建会话，但不替用户悄悄切换。

上下文较长时，将较早内容压缩为摘要，并保留近期消息。摘要用于降低上下文成本，原始记录仍按保存策略保留；用户删除时，相关摘要和检查点也要处理。LangGraph 区分线程内短期记忆与跨线程长期记忆，可以据此组织实现。[LangGraph 记忆说明](https://docs.langchain.com/oss/python/concepts/memory)

### 到底召回什么

| 信息类别 | 例子 | 使用方式 |
| --- | --- | --- |
| 当前会话上下文 | 最近问答、当前文件、尚未完成的步骤 | 当前会话直接使用 |
| 较早会话摘要 | 上周对某个问题的结论 | 主题相关时召回，能追溯原会话 |
| 长期偏好与事实 | 喜欢简短中文回答、正在研究某项目 | 经确认后跨会话使用 |
| 知识库证据 | PDF 页码、文章段落、收藏备注 | 根据问题检索并显示引用 |
| 任务状态 | 待整理资料、草稿位置、待确认发布 | 从任务记录读取，不依赖模型猜测 |

“把所有聊天记录做成向量库”不是必要的第一步。先保证当前会话连续、文档检索可靠，再加入少量确认过的长期记忆。

每条长期记忆至少记录所属用户、内容、来源、更新时间和是否已确认；必要时增加到期时间。冲突信息应更新或请用户确认，不能把旧偏好永久当真。

### 是否对 userID 做性格总结

首版不做自动性格画像。userID 只是身份与数据归属标识，不能说明这个人的性格。

站长可以开启少量实用偏好记忆，并在设置页查看、修正和删除。普通用户默认只保留必要的会话记录；将来要提供跨会话记忆时，由用户主动开启。避免把一句临时情绪或角色扮演内容写成长期人格结论。

### 后端最少记录什么

- 账号：稳定用户 ID、验证状态、角色、创建时间、禁用状态。
- 会话与消息：所属用户、公开或私人模式、消息内容、时间、引用来源、删除状态。
- 任务与工具：输入参数摘要、执行状态、确认记录、结果位置、失败原因。
- 资料：文件归属、可见性、解析状态、版本、分块与页码映射。
- 记忆：经过筛选的偏好或事实、证据与更新记录。
- 用量：模型与搜索调用次数、输入输出 token、并发与预算消耗。

聊天展示与日常日志只保存必要的用户可见结果、工具事件和审计信息。若选定供应商协议要求工具续接时回传额外模型字段，由适配层维护在隔离的运行状态中，不展示给其他用户，不混入公开知识或普通日志。日志尽量避免复写全文私人资料。

## 7 小规模知识库与网页链接

### 首版资料范围

知识库先按小规模试用设计，支持公开网页链接、文本型 PDF 和 DOCX。网页链接作为主要入口之一，与文件上传同等优先。

首版不支持旧版 DOC 和扫描件 OCR，不安装或接入相应转换流程。遇到 DOC 时提示转换为 DOCX；遇到扫描 PDF 时提示提供含文本层的 PDF。解析器保留扩展位置，但没有提取到正文的文件不得标记为已成功入库。

统一流程为：接收文件或链接 → 校验 → 获取正文及来源 → 解析 → 分块 → 建立索引 → 标记可用。处理作为可查询、可重试的后台任务；未完成时，助手说明仍在处理。

### 链接收藏与正文入库分别控制

收藏一条链接只需要 URL、标题、站长备注和标签；正文入库则额外保存可检索的网页正文与版本。两者互相引用，可以只收藏而不抓取，也可以对已有收藏补充入库。

首版默认建议：站长只说“收藏这个网址”时保存链接，必要时获取标题；明确说“收进知识库”或“收藏并入库”时才抓取正文。可提供站长偏好“新收藏默认入库”，由助手修改，但不静默启用。

网页来源保存原始 URL、最终 URL、标题、抓取时间、内容摘要指纹、快照版本和解析状态。规范化与去重不得随意删除可能改变网页内容的查询参数。新增版本不覆盖旧版本，已有回答的引用能追溯当时资料。

首版抓取单页正文，不默认递归抓取整站，只支持无需登录的第三方公开页面。登录墙、动态页面或访问失败显示原因，可由站长粘贴正文或上传导出文件补充。第三方页面的登录限制与“秋序公开浏览免登录”分别处理，不混为一个开关。

刷新先由站长手动发起。已公开的内容固定到明确版本，新抓到的正文默认作为私密的新版本，不自动扩大公开范围。以后再增加定期检查更新的选项，当前不创建自动抓取任务。

### 引用与检索

PDF 回答显示文件名与页码；Word 优先显示章节或段落位置；网页显示标题、原链接、抓取日期及引用片段。问答没有足够证据时说明缺口，不把模型补充内容伪装为资料原文。

资料进入知识库属于检索增强，不是重新训练模型。先使用单一资料库配合严格的权限过滤，观察效果后再优化分块、关键词检索与向量检索的组合。

替换、删除或收回公开权限时，原文件、快照、分块、向量索引和缓存按同一对象关系处理。从资料抽取的记忆、摘要与任务上下文保留来源依赖，防止删除或撤权后仍被召回。默认永久保存意味着不自动过期，并不阻止站长主动删除。

### 站内检索与联网搜索

普通用户只查询允许公开 AI 使用的本站内容，不获得搜索和网页抓取工具。站长可以选择自动、站内或联网模式；模型只能从当前身份获准的工具中选择。

联网搜索返回新来源及检索时间；站长选择收藏或入库后才持久保存为知识资料。站长的普通问答与联网调用分别计量，并共同计入站长额度；普通用户按自己的账号计量，所有调用同时计入全站预算。

抓取服务限定可访问的公开 HTTP 或 HTTPS 地址；检查解析后的 IP 和每次重定向，禁止本机、内网与元数据接口，限制体积和耗时。网页、PDF 与 Word 内的指令性文本只作为资料，不改变授权或自动触发操作。

## 8 账号冷却与额度

冷却期与限流解决不同问题：冷却期降低刚注册即滥用的概率；限流限制每段时间、每个账号和全站的资源消耗。二者都需要在服务端检查。

已确定：邮箱验证成功后冷却 24 小时，冷却结束后每个普通账号每日最多 10 次 AI 请求，均可由站长调整。一次用户发起的有效问答算一次，不将同一请求内部的工具步骤重复计数；并发提交时在服务端原子预占额度，重试使用请求 ID 去重。每日重置时间建议为 Asia/Shanghai 的 00:00。其余限速数值仍为初始建议。

| 控制项 | 当前值或策略 |
| --- | --- |
| 账号激活 | 邮箱验证后激活 |
| 新账号 AI 冷却 | 验证成功起 24 小时，站长可手动解除 |
| 冷却中的留言 | 可以提交，首条或新账号留言进入审核 |
| 普通用户问答 | 已定每日 10 次；建议每分钟最多 3 次、最多 1 个进行中的任务 |
| 普通用户联网搜索与网页抓取 | 不开放；仅站长拥有对应工具 |
| 站长额度 | 独立较高额度，同时保留每日预算与并发上限 |
| 全站保护 | 注册与登录限速、全站预算上限、异常调用熔断 |

仅按账号计数容易被批量注册绕过，可辅以 IP 限速和必要时的人机验证。对于共享网络，应避免单凭 IP 就永久封禁。

次数之外，还要限制单条输入长度、输出 token、文件大小、工具调用次数和任务运行时间。失败与取消的请求是否扣次数可以按产品规则定义，但第三方实际产生的费用仍要计入预算。

用户界面显示剩余额度、冷却结束时间及失败原因。不能只让模型口头拒绝，因为进入模型前就可能产生费用。

## 9 前后端分离与后端 Agent 合并

### 项目边界

采用传统前后端分离：前端通过 HTTP API 与流式事件连接 FastAPI；FastAPI 内部同时包含业务模块、Agent 工作流和工具适配。Agent 作为后端的一部分重新设计，不依赖现成独立 Agent 服务。

前端不直接调用模型，不持有模型密钥，也不承担最终身份和数据权限判断。即使选用 Next.js，也不在它的服务端重新实现一套业务后端。FastAPI 可以按路由与模块组织应用，适合这种同项目内分工。[FastAPI 多文件应用](https://fastapi.tiangolo.com/tutorial/bigger-applications/)

核心调用关系为：前端 → FastAPI 接口 → 身份与权限检查 → 业务服务或 Agent → 相同的业务服务 → 数据存储。Agent 工具调用服务层函数，表单接口也调用这些函数，不在后端内部绕一圈 HTTP 请求自身接口。

英文名已确定为 Autumn Prelude，初始仓库名为 autumn-prelude。仓库采用 frontend 和 backend 两个目录；前后端独立安装依赖、运行与构建，后端和 Agent 位于同一项目。初始内容以需求、设计素材和目录说明为主，应用实现随后推进。

```text
项目仓库
├─ frontend/                  页面、聊天、上传、像素角色与管理表单
├─ backend/
│  ├─ app/api/                身份、内容、知识库、对话、设置接口
│  ├─ app/auth/               登录、额外验证、权限上下文
│  ├─ app/services/           文章、收藏、可见性、保存策略等业务规则
│  ├─ app/agent/              角色、工作流、工具白名单、记忆与状态
│  ├─ app/ingestion/          网页抓取、PDF 与 Word 解析、索引
│  ├─ app/jobs/               解析、重试、清理等后台任务
│  └─ app/storage/            数据模型与数据库访问
└─ docs/                      产品约定、接口契约与验证说明
```

“写在同一个后端”不要求所有任务在同一个请求里完成。网页解析等后台任务可以运行在同项目启动的 worker 中，共用业务模块与权限规则，不拆成独立 Agent 产品。

### 技术建议

| 层次 | 当前建议 | 作用 |
| --- | --- | --- |
| 前端 | Next.js 与 TypeScript，框架尚可调整 | 内容页面、聊天、文件上传与像素角色 |
| 后端 | FastAPI 与 Uvicorn | 统一业务、认证、接口与流式响应 |
| Agent | LangGraph 加按需使用的 LangChain 组件 | 有状态任务、模型工具调用、暂停恢复 |
| 数据 | PostgreSQL 加 pgvector | 内容、会话、设置与资料向量索引 |
| 文件 | 本地试用使用持久化目录与存储适配层 | 原始文件及网页正文快照 |
| 作业与限流 | 可替换的队列和计数接口，需要时引入 Redis | 解析、重试、跨进程用量控制 |

先把业务和权限流程跑通，不为小规模知识库引入多个检索数据库。pgvector 支持在 PostgreSQL 内做向量相似度搜索。[pgvector 项目说明](https://github.com/pgvector/pgvector)

### 模型 搜索与知识库服务

已选服务是 DeepSeek、Tavily 和阿里云百炼。三者不必都承担对话模型职责，建议按下列方式分工；具体模型 ID、接入地域、额度与百炼的最终用途在配置阶段确定。

| 服务 | 建议职责 | 权限与实现边界 |
| --- | --- | --- |
| DeepSeek | 对话、角色表达、任务理解与工具调用 | 普通用户与站长共享模型适配层，工具和资料权限不同 |
| Tavily | 站长联网搜索；网页正文提取可选使用 Extract | Search 与 Extract 分开计量；普通用户不能调用 |
| 阿里云百炼 | 知识库文本向量化；需要时增加重排序 | 首版建议采用向量服务，重排序按检索质量决定是否启用 |

DeepSeek 的官方工具调用文档可作为接入依据，具体实现先验证所选模型和模式的协议。[DeepSeek Tool Calls](https://api-docs.deepseek.com/guides/tool_calls/)

Tavily 提供面向应用的网页搜索；抓取指定网址与搜索新资料在业务上分别授权，不因为使用同一服务商而合并权限。[Tavily Search](https://help.tavily.com/articles/4840311948-tavily-search-api)

百炼提供文本向量与重排序模型，因此可以承担知识检索相关能力；这是本项目的分工建议，不要求把网站内容管理或权限控制迁入托管 Agent 平台。[百炼向量与重排序](https://help.aliyun.com/zh/model-studio/embedding-rerank-model)

模型名、服务地址、超时和预算通过配置传入，真实密钥只放后端本地环境或受控配置，不提交仓库。更换嵌入模型或向量维度时需要生成新索引版本并重新入库，不能把不同向量空间的数据混在同一索引中。

### 首批接口职责

| 接口或接口组 | 职责 |
| --- | --- |
| 邮箱注册 验证 登录 找回密码 | 邮箱加密码登录；密码保存安全哈希，验证与重置凭据具有有效期和重试限制 |
| 管理员额外验证 | 激活有时效的站长权限，不依赖模型判断身份 |
| POST /api/ask | 统一自然语言入口；服务端决定身份、资料和工具 |
| conversations 与 runs | 查询自己的历史、任务状态、取消与恢复 |
| knowledge/files 与 knowledge/urls | 文件上传、链接入库、解析状态、刷新与删除 |
| content 与 visibility | 文章、收藏的编辑与公开设置；供表单与工具共用 |
| actions | 保存具体操作、预览、必要时确认、执行记录与撤销 |
| settings/retention | 查询或修改保存策略，明确是否影响已有数据 |

这些辅助接口不改变统一问答入口的设计。前端可通过表单调用，站长也可通过对话触发同样的业务服务。

流式事件包括文本片段、引用来源、任务状态、操作结果、待确认事项、错误与完成。它们同时驱动像素小形象。身份和权限上下文由服务端注入，不能接受模型或客户端自行填写的管理员身份。

### 执行一致性

每次任务使用请求 ID 与运行 ID；写操作带幂等标识，重复提交返回同一次操作结果。操作记录包含对象 ID、执行前后版本、实际变更和状态。页面只在收到提交成功事件后显示“已修改”。

LangGraph 的持久化能力用于恢复任务；业务写入、权限同步与副作用去重由应用负责，不把检查点视为所有外部动作恰好执行一次的保证。[LangGraph 持久化](https://docs.langchain.com/oss/python/langgraph/persistence)

### 部署范围

当前不选购服务器、不配置域名、不部署公网服务。开发只保留环境配置、持久化存储和未来部署所需的合理边界；正式上线的网络、邮件服务、备份与容量方案以后单独安排。

## 11 永久保存与可调整的期限

### 当前保存策略

文章、收藏、聊天和日志全部默认永久保存；知识库原文件、网页快照与必要任务记录也按不自动过期处理。永久表示没有自动到期时间，不表示用户不能主动删除，也不表示必须全部加载进每轮模型上下文。

| 数据 | 当前期限 | 默认可见性 |
| --- | --- | --- |
| 文章与草稿 | 永久 | 新建私密，站长动态设置 |
| 收藏 链接备注 网页快照 | 永久 | 新建私密，公开字段分别指定 |
| 知识文件与索引 | 永久 | 新建私密，公开版本由站长指定 |
| 聊天与摘要 | 永久 | 仅本人；分享时生成独立版本 |
| 操作审计与运行日志 | 永久 | 管理区可访问，避免记录密钥等敏感字段 |

日志轮转只把旧日志移至归档存储，默认不删除归档；需要监控存储增长。备份也不在本轮设置自动过期规则，将来安排部署时再明确策略。

### 预留的策略与接口

保存策略按数据类型记录：保存模式、期限天数、时间起点、适用范围、生效时间和策略版本。当前统一为 forever，期限为空，到期时间为空；查询和修改均经过后端鉴权。

期限改变时区分“只对之后新建的数据生效”与“同时作用于历史数据”。不能因为站长说“以后保存半年”，就直接删除现有超过半年的记录。助手先列出受影响数量、时间范围与处理方式；可能清理已有内容时，需要明确选择后执行。

预留策略查询、影响预览、策略更新、归档、软删除与彻底清理接口。自动到期清理只有在明确启用有限期限策略后才生效；当前保持关闭。策略本身可调整，但已经彻底删除的数据不能靠把期限改回永久恢复。

账号本人删除聊天、站长删除资料仍走独立的主动删除流程。涉及消息摘要、记忆、分块、向量、快照和缓存时，根据对象依赖同步处理；审计记录保留操作结果和必要元数据，避免再次保存已删除的私人全文。
