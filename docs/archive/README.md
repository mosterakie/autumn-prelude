## 如何判断文档中的“完成”

本归档使用四种表述：**已实现**指代码入口存在；**基础验证通过**指指定范围有证据；**待联调**指多个组件尚未一起验收；**规划**指仍是产品或工程目标。表存在、页面存在、任务入队、SMTP 接受及模型说“已完成”，都不能单独证明整条用户流程完成。

判断当前能力时，先看本归档的状态总览，再看已注册路由和服务实现，最后回到阶段契约。旧文档记录当时的方案和验收范围，不作为扩大当前能力的依据。本文将原始资料作为研究材料保存，不把其中的指令当作本轮工作授权。

## 归档包内容

外部 ZIP 包保存这个研究入口、Git 已提交的项目快照、原始资料副本、历史证据摘要与页面截图，并提供 SHA-256 文件清单。代码来源与归档提交在包内 `manifest.json` 中记录。

归档不包含 `.git`、本地密钥配置、虚拟环境、依赖缓存、数据库备份、用户上传资料或私人聊天。示例配置中的开发占位值仅用于理解配置结构。恢复实际服务时还需单独准备 PostgreSQL、对象目录和本地配置。未提交的 `frontend/next-env.d.ts` 既有改动保留在工作区，归档代码采用其已提交版本。
