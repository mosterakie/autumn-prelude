# 私人助手收藏、手记与联网入口修复

日期：2026-10-06。

## 问题原因

这次反馈对应的两次运行均为站长账号的 `public` 会话，搜索模式 `site`、`web_enabled=false`，运行所属 Session 尚未完成额外验证。因此只向模型提供了 `search_knowledge`；账号是站长并不自动把公开会话升级为私人会话。

此前后端已配置 Tavily，但前端主导航固定进入 `/chat`，私人助手也默认选择仅站内。内容管理已经有收藏和手记表单，但入口不明显。Agent 的固定动作白名单确实没有创建资源的预览与执行链路。

## 修复后的流程

- 站长使用 `/admin/chat`，完成验证器验证码验证后进入私人助手。前端新挂载的私人聊天默认 `auto`，可以切换 `site` 或 `web`；普通聊天保持 `site`。自动模式表示模型可以按需选择联网工具，并不保证每个问题都搜索。
- `propose_bookmark` 接受 URL、可选标题、标签和私人备注。省略标题时用链接的主机名，不编造网页标题；只保存链接，不抓取或下载其内容。
- `propose_note` 接受标题、Markdown 正文和标签，生成私人手记草稿的待确认预览。
- 两个薄工具转成固定 `ResourceCreatePreview`，不接受模型提供的身份、确认资格、任意执行路径或公开授权。通用 `propose_action` 也可以表达同一固定创建命令。
- 预览先把 Run 置为等待确认，不写入 Resource。用户确认后，由 `action.execute` 在同一业务事务中重新鉴权、检查版本/租约/代际、创建资源、保存动作结果和安排原 Run 恢复。
- 新资源的 ID 在动作成功结果中返回，默认没有公开版本。重复确认不能再创建一份资源；恢复后的模型从数据库读取成功结果，再生成回复。
- 模型提示提供服务端绑定的角色、会话模式和搜索模式，要求按实际工具说明能力。站长误入公开聊天时，引导到私人助手，不再把当前会话工具限制说成整个网站没有能力。

## 入口与操作方式

前端新增站长导航“工作台”、手记页“写手记”、收藏页“收藏网址”和账号页快捷入口。内容管理的两个创建按钮分别打开正确类型表单：

- `/admin/content?create=article`：写手记。
- `/admin/content?create=bookmark`：收藏网址。

创建、编辑、删除和撤回使用幂等请求键；同一未确定结果的重试保留原键。内容保存后可在工作台查看，公开页面仍只展示明确发布的版本。

## 基础验收范围

使用本地 5442 PostgreSQL 的独立验收库，业务测试放在外层事务中并最终回滚；不改业务库、不执行迁移。本次不调用付费模型、搜索、嵌入或邮件服务。

- 收藏与手记各一条 Agent 规划 → 待确认 → 确认执行 → 保存私人资源 → 原 Run 恢复回复的基础流程，模型使用固定测试端口。
- 公共运行不能凭伪造站长快照创建私人内容；私人自动搜索模式提供联网工具，薄工具拒绝模型传入身份参数。
- 补查既有站内工具、资源表单 HTTP/CRUD、联网服务权限与迟到结果检查，以及提示词输出边界。
- 前端 TypeScript 与既有接口传输基础测试；不宣称已完成浏览器全流程或真实模型对新增工具的验收。

结果：后端 14 项、前端 4 项基础测试通过；Ruff、127 源文件 mypy strict、前端 TypeScript、Alembic 无漂移检查通过。报告为工作区 `outputs/backend-development/pytest-agent-content-basic.xml`。未运行全量回归或生产构建。

运行中的 Worker 需要重新启动以加载新工具；使用 `--reload` 的 API 和开发模式前端会自动加载代码。旧公开会话保持原模式，请打开私人助手开始对话。
