## 当前配置位置

所有后端设置由 [config.py](src/autumn_backend/config.py) 的 Settings 读取，环境变量统一使用 AUTUMN_ 前缀。

| 文件或来源 | 当前作用 |
| --- | --- |
| [.env.example](.env.example) | 通用配置模板，目前没有邮箱发送字段 |
| backend/.env | 常规本地配置文件；当前工作区尚未创建 |
| backend/.env.providers.local | 当前已有的本地供应商配置，已被 Git 忽略 |
| 进程环境变量 | 可以覆盖文件中的同名设置 |

文件读取顺序为 .env、.env.providers.local，后者覆盖前者同名值；进程环境变量优先于这两个文件。新建 .env 时应填写其中的通用配置，尤其不要保留空白安全密钥；改动设置后重新启动 API 和 Worker。前端 .env.local 只用于前端自身配置，不承担邮件密码或发送功能。

当前 Settings 配置 extra=ignore，未声明的环境字段会被忽略。因此直接添加 AUTUMN_SMTP_HOST 等自行命名的变量，仍不会发出邮件。

## 当前注册和找回密码如何工作

注册、重发验证和找回密码通过 AuthService 创建一次性令牌，并在同一事务中安排 auth.email 任务。数据库保存令牌哈希，任务仅保存用途、对象标识、加密版本及令牌密文；邮箱在发送时应按账号标识重读。

邮箱验证令牌有效 24 小时，密码重置令牌有效 1 小时。验证成功后，普通账号才解除未验证限制，并按站点设置进入 AI 冷却期。密码登录本身不需要 SMTP；未验证账号即使能登录，也不能因此获得留言或 AI 操作权限。

默认 Worker 的注册表没有 auth.email 处理器，所以相关任务保持排队，浏览器收到受理成功并不代表收到了邮件。站长额外验证使用验证器 TOTP 或恢复码，与邮箱发信配置是两条独立路径。

## 接入前准备哪些信息

选择你准备使用的邮箱服务商，并从其官方说明或控制台取得以下参数。具体服务器、端口和加密方式以该服务商提供的设置为准，本说明不预设某家服务商。

| 信息 | 用途 |
| --- | --- |
| SMTP 主机、端口、加密方式 | 连接发送服务；明确是直接 TLS 还是 STARTTLS |
| SMTP 登录用户名 | 服务商要求的发件账户身份 |
| SMTP 密码、授权码或应用密码 | 以服务商要求为准；通常与网站用户的登录密码无关 |
| 发件邮箱与显示名称 | 收件人看到的发件身份；须符合服务商允许的发件地址 |
| 网站前端完整地址 | 生成验证邮箱、重置密码的可访问链接；本机可使用 http://localhost:3000 |

这些资料准备好后仍需要开发接入，不能直接照表添加环境变量就视为完成。

## 实际启用前还需开发的步骤

1. 在 Settings 和 .env.example 声明邮件配置、网站链接基址及校验规则，密码采用 SecretStr；届时将真实值填写到被忽略的本地配置中。
2. 增加 SMTP 发送适配器和固定验证/重置邮件模板，将实际前端页面地址放入链接。
3. 实现 auth.email 处理器：发送前检查账号、令牌用途、有效期及任务租约，解密仅限发送边界，网络调用放在数据库事务外；结束时安全清理密文，错误信息不包含链接令牌或凭据。发送结果未知时不能直接当作明确失败无限重发。
4. 在默认 Worker 中按有效配置注册邮件处理器，并进行少量基础验收；最后由站长使用自己的测试收件箱验证注册和重置链接。
